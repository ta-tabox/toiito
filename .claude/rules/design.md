# 画面の規範

値と現況の正は `docs/DESIGN.md`、なぜこの見た目かは `docs/VISION.md`「設計原理」。
ここが持つのは画面に当てる規則だけで、値と矛盾したらこちらが勝ち、上位（`docs/VISION.md` > `docs/ARCHITECTURE.md`）と矛盾したら上位が勝つ。
規則は「〜する」の形で書き、禁じる形で残すのは「やらないこと」の一覧だけにする。

## 語彙

画面に出る語（工程名・アクション名・`status` のラベル）は `docs/VISION.md`「語彙」節の語を使う。

## 彩度の規律

- 面（吹き出し・ピル・入力欄の背景）は彩度を持たず、暖と寒の傾きだけを持つ
- 彩度を持つのは人間の発話（緑の面）・自分が付けたメモの下線（琥珀）・サインインできなかったことを伝える枠（警告色）の三つだけにする。
  色数が増えるほど下線が沈むので、彩度を持つ面が四つ目に出たらそこが破れ目
- ログインの画面はメモの下線を持たず、警告色を置いても下線が沈まないので、警告色はログインの画面の枠にだけ使う
- 人間の発話は淡い緑に留める。
  吹き出しは面積が大きく、濃い緑で白抜きにすると塊になる。
  濃い緑を使うのはボタンだけ

## 話者の描き分け

- 三者は同じ幅で並べる。
  二体は対等で、主と従を作らない
- 二体を分けるのは温度と枠の形で、どちらにも彩度を使わない
- 温度は周辺視の手掛かりでしかないので、名前のラベル（`具体` / `抽象`）を残す

## 書体と字組み

- 問いは明朝、対話はゴシック
- 欧文と数字は和文の従属欧文で出す（欧文専用の書体を混ぜると、和文と欧文で字面の大きさとベースラインが揃わない）
- 数字が縦に並ぶ箇所は `font-variant-numeric: tabular-nums`
- 字の大きさの段は 12px と 14px のどちらかに寄せる（間の段は Tailwind の刻みに無く、自前のテーマが要る）
- 入力欄は 16px 以上にする（iOS Safari は 16px 未満の入力欄で自動でズームする）。
  拡大は `user-scalable` の既定のまま残す
- 読み下す文章の行間は 1.9 以上、一行は全角 34 字以内

## 余白と密度

- 間隔は 8px の倍数にする
- 密度を上げる方向の変更を既定で疑う

## 重心

- 既定は読み。
  入力欄は本文の下に細い一行で待ち、背景も影も持たない
- 入力へ触れた瞬間だけ書きの間へ移り、書き終えるか外を触れば戻る
- 入力欄は本文の流れの中に置き、常設の固定入力欄は置かない。
  常に手の届く入力欄は常に返答を促す形になる。
  メモの入力欄は語を選んでいるあいだだけ出るので、これに当たらない

## 状態の見せ方

- `status` の 7 値のピルは地を一律にし、先頭の点が開／閉の一ビットだけを持つ
- 応答を待っている間に出す指標は「二体が応答中」の一つにする
- 過去のセッションは読み取り専用にし、痕跡は弱く添えるだけにする

## 動き

- AI の応答は行を上から置く（一字ずつ打たない）
- 本文は最初から DOM に置き、動かすのは不透明度と位置だけにする。
  `web/src/components/message-body.tsx` が文字オフセットでアンカーを持つので、描画の途中で文字を選んでもずれてはいけない
- `prefers-reduced-motion` では落差も遅延も無しで出す
- 動きは読みの助けになるものだけにする（ホバーで吹き出しを拡大するような、注意が道具へ向く動きは作らない）

## 対応範囲

- スマホ第一。
  iPhone の幅で成立するかで判断し、デスクトップは中央一列を広げるだけにする
- 色はトークンの二組（明と暗）のどちらにも値を持つ名前で指定する。
  片方だけに固定した値は、明暗のどちらかで読めなくなる

## 部品の型

- 共通部品は `web/src/components/ui/` へ切る
- 部品は自前で書く。
  UI ライブラリは既定が快適な SaaS の見た目なので、離れるより寄せる方が楽になる
- 同じ className の並びが 3 箇所に出たら切る。
  2 箇所では切らない（`.claude/rules/coding.md`「YAGNI」）
- CSS とテストが DOM を指すときは `data-*` 属性で指す（一覧は `layers.md`「プロジェクト固有」）

## やらないこと

- 状態を 7 色に分ける
- 常設のサイドバー・タブバー（読み書きする画面は `/`・`/q/[id]`・`/memos` の 3 枚で、`/login` はそこへ入るまでの通り道）
- 通知
- 進捗インジケータの類（進み具合そのものが目的になる）
- アバターと検索
- 二体への固有名（`具体` と `抽象` であって、人格の名前を持たない）
- 画面の英語
- 速く見せる演出（スケルトン・プログレスバー・楽観的更新）
- `docs/DESIGN.md`「残す摩擦」の左列を削る
