# Python への写像

核（`coding.md`）の原則を Python のイディオムへ写す。
書き方だけを持ち、toolchain（uv / ruff / mise）の設定は持たない。

## 不変を既定に
- データ保持は `@dataclass(frozen=True)` か `NamedTuple` を第一候補にする
  `@dataclass` 自体は Data Class 臭とは無関係で、検証は `__post_init__`、計算はメソッドとして同じクラスに同居させれば健全（ロジックを外に出したときだけ悪臭）
- 既定引数には不変の値か `None` 番兵を置き、可変の値は関数内で生成する（`def f(x=[])` は呼び出し間で共有される）
- 設定は生成時に注入する
  モジュールレベルの可変グローバルは、読む側と書く側の順序を暗黙にする

## 不正状態の表現不能化
- 型ヒントは公開関数で必須
  `Any` は `object` + 絞り込みか型変数で置き換える
- 状態の直和は `Union` + パターンマッチ、または状態ごとの dataclass で表す
- ドメインの概念（ID、金額、範囲）は `NewType` か値オブジェクトで表し、生の型に埋没させない

## 関数・エラー
- 「無い」の表現: コレクションは空を返す / 正常系の欠損は `T | None` を型で明示する / 異常系は例外
  `None` を暗黙に返す関数（return 忘れ）は型ヒントで露わにする
- 例外は具体的な型で捕り、回復できないなら再送出する
  `except Exception: pass` は握りつぶしである
- 「空」と「無い」を区別すべき場面では `is not None` で明示する
  真偽値の暗黙変換（`if items:`）は両方を同じに扱う

## 命名
- PEP 8 準拠（snake_case / PascalCase / UPPER_SNAKE）
  ruff に委ねる
- ゲッターはプロパティか素の名前にする
  `get_` は Java の癖

## 余白
- PEP 8 の vertical whitespace: トップレベル定義の間は 2 行、クラス内メソッド間は 1 行
  関数内は論理ブロックごとに 1 行（連続 2 行はトップレベルの区切り専用）
- ruff が見るのは定義周りの空行（E301–E306）だけ
  関数内部の区切りは自分で入れる
- 内包表記は 1 段まで
  ネストや条件が絡んだら for 文へ戻す

## docstring
- モジュール冒頭に docstring を置く
  PEP 257 の形（1 行要約 → 空行 → 本文）に従い、要約は「何に責任を持つか」を能動で書く
- docstring には型が語れないこと（単位・不変条件・例外を投げる条件・呼び出し順の制約）を書く
  `:param x: x` の形は型ヒントと重複する
- black / ruff format は docstring とコメントの**内部を折り返さない**
  折り返さない以上、改行位置は書き手が**句点でのみ**入れる（読点や節の境界では折らない）
