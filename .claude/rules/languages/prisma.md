# Prisma スキーマへの写像

核の原則（`coding.md`）を Prisma スキーマのコメントへ対応付ける。
上の `paths` に当たるファイルを Read した時点で読み込まれる。
生成された TS のコメント規約は `typescript.md`「コメント / JSDoc」が持つ。

## コメント

TS と同じ「宣言に付く説明は doc コメント」を守るが、**記号は `///`**。

- **model / enum / field / datasource に付ける説明は `///` で書く**。
  これが Prisma の doc コメントで、生成される TS に JSDoc として出力される（`/// 問い。…` → `* 問い。…`）
- 宣言の直前に置く説明は `///` に限る。
  `/** */` は構文としては通るが、Prisma が行頭の `*` ごと本文として取り込んでから JSDoc に包み直すので、生成物が `*  * 本文` と二重になる
- 宣言に付かない説明（ファイル冒頭・generator ブロックの前）は `/** */` でよい。
  どの宣言にも紐づかないため生成物に影響しない
- DB の制約のうちスキーマで表現できないもの（check 制約）は、migration の SQL に置き、該当する model のコメントに何が効いているかを書く
