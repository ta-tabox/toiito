# 0044. 利用者の API キーを暗号化して DB に置き、鍵を環境変数に置いて鍵 ID で回転する

- **状態**: 採用
- **決定日**: 2026-09-15
- **関係する ADR**: 0018, 0022, 0024, 0043, 0045

## 文脈

0043 は、モデルと API キーを AI を呼ぶ時点で利用者ごとに解決すると決めた。
#70（ユーザーごとのモデル選択と API キー（BYOK））は、高いモデルを使いたい利用者が自分の API キーで使うことを求めている。

利用者の API キーは、その利用者の課金に直結する秘密である。
漏れると、第三者がその利用者の費用で API を呼べる。
#70 は平文で持たないことを前提に置き、保存するかどうか・暗号化の鍵の置き場・DB が漏れたときの影響範囲を決めることを求めていた。

置き場を決める事実は次の三つである。

| 事実 | 出所 |
|---|---|
| ログインのセッションは 1 日で切れ、使っても延びない | ADR 0022 決定 3 |
| Preview は、本番のデータが無いことを条件に露出を受け入れている | ADR 0022 決定 10 |
| DB（Neon）と実行環境（Vercel）は別の事業者が持ち、本番の秘密は実行環境の環境変数に置く | `docs/DEPLOY.md`「秘密の置き場」 |

## 決定

### 置き場

1. **利用者の API キーは、暗号文だけを DB に置く。**
   平文は DB・ログ・画面・エラー文のどこにも出さない。
2. **復号は AI を呼ぶ直前にサーバーで行い、復号した値を保存しない。**
3. **利用者は自分のキーを登録・差し替え・削除でき、画面が返すのは登録済みかどうかだけとする。**

### 暗号化

4. **暗号化は認証付きの共通鍵暗号にし、暗号文ごとに乱数の初期化ベクトルを持たせる。**
   書き換えられた暗号文は、復号の時点で失敗する。
5. **暗号化の鍵は実行環境の環境変数に置き、DB とリポジトリに置かない。**
6. **暗号化の鍵は他の秘密から導出せず、独立した値として持つ。**
7. **本番と Preview は別の暗号化の鍵を持つ。**

決定時点の例として、暗号方式は AES-256-GCM で、Node の標準の暗号モジュールで足りるので依存は増えない。
環境変数の名前と、暗号化と復号を閉じるモジュールの現況は、`web/README.md` と `.claude/rules/layers.md` が持つ。

### 回転

8. **暗号文は、暗号化に使った鍵の ID を持つ。**
   復号は、暗号文の鍵 ID で鍵を選ぶ。
9. **回転は、旧い鍵と新しい鍵を併記した状態で、次の順に行う。**

| 段 | 行うこと | 復号できる暗号文 |
|---|---|---|
| 1 | 新しい鍵を足し、旧い鍵と併記する。以後の暗号化は新しい鍵で行う | 旧い鍵・新しい鍵 |
| 2 | 旧い鍵の暗号文を、すべて新しい鍵で暗号化し直す | 旧い鍵・新しい鍵 |
| 3 | 旧い鍵の暗号文が残っていないことを確かめてから、旧い鍵を外す | 新しい鍵 |

手順の現況は `docs/DEPLOY.md`「秘密の置き場」が持つ。

## 理由

### 置き場

- **DB に保存する**: ログインのセッションが 1 日で切れる（0022 決定 3）ので、保存しない案では利用者が毎日キーを入力することになる。
- **暗号文だけを置く**: 暗号化の鍵が DB と別の事業者の環境変数にあるので、DB だけが漏れてもキーは復号できない。
- **復号した値を保存しない**: 平文が残る場所を、呼び出しの間のメモリだけにする。
- **画面は登録済みかどうかだけを返す**: キーの一部でも画面へ返すと、画面の応答がキーの漏れる経路になる。

採らなかった案。

- **ブラウザにキーを持たせ、発話ごとに送る**: DB が漏れても影響は無いが、キーが毎回リクエストに載り、ページのスクリプトから読める位置に置かれる。
  ブラウザを替えるたびに入力も要る。
- **ログインのセッションの間だけサーバーが持つ**: 保存の期間は短くなるが、1 日ごとに再入力が要り、その間は結局暗号化して置くことになる。
- **外部の鍵管理サービスに鍵を置く**: 運営者でも鍵を取り出せない形にできるが、依存が一つ増え、手仕舞いで閉じる相手が増える（0018 が magic link を採らなかった理由と同じ型）。
- **キーのハッシュだけを置く**: ハッシュからは API を呼べない。

### 暗号化

- **認証付きの暗号にする**: 書き換えた暗号文が別の値として復号されず、失敗として検出される。
- **暗号文ごとに乱数の初期化ベクトルを持たせる**: 同じキーを登録した二人の暗号文が同じにならない。
- **独立した鍵にする**: `BETTER_AUTH_SECRET` から導出すると、#150（外周の守りを決める）の回転手順でセッションを切るたびに、全員のキーも読めなくなる。
- **本番と Preview で鍵を分ける**: Preview は露出を受け入れている（0022 決定 10）ので、Preview の鍵で本番の暗号文が読めてはならない。

採らなかった案。

- **`BETTER_AUTH_SECRET` から暗号化の鍵を導出する**: 環境変数は増えないが、上のとおり二つの秘密の回転が連動する。

### 回転

- **暗号文に鍵 ID を持たせ、併記して回転する**: 回転の間も全員のキーが復号できるので、回転が利用者の対話を止めない。
- **旧い鍵を外す前に、残りが無いことを確かめる**: 外した後に残った暗号文は、どの鍵でも復号できなくなる。

採らなかった案。

- **回転したら全員に再登録させる**: 鍵 ID も暗号化し直す手順も要らないが、回転のたびに全員のキーが使えなくなる。

## 帰結

| 対象 | 変わること |
|---|---|
| 運営者 | 暗号化の鍵と DB の両方に触れられるので、技術的には利用者のキーを復号できる。画面に出さないことは、運営者に対しては規律で守る |
| `docs/DEPLOY.md`「秘密の置き場」と Preview の表 | 暗号化の鍵が本番と Preview に一本ずつ加わる。回転の手順が、#150 の `BETTER_AUTH_SECRET` の回転手順と同じ節に並ぶ |
| `docs/DEPLOY.md`「Preview では次を守る」 | Preview はフェイクモードでキーを使わないが、保存はできるので、実キーを入力しない規則が加わる |
| `web/README.md` の環境変数の表と `web/.env.example` | 暗号化の鍵の変数が加わる。`.env*` は Claude が書けない（ADR 0024）ので、`web/.env.example` の更新は人間が行う |
| `.claude/rules/layers.md` | 暗号化の鍵を環境変数から読むモジュールが、`process.env` を読むモジュールの一覧に加わる |
| データモデル | 利用者のモデルとキーの設定を持つ行が、所有のルートとして一つ加わる。利用者を削除すると、その行も削除される |
| 暗号化の鍵が失われたとき | 全員のキーが復号できなくなり、利用者に再登録を求めることになる |

## 覆る条件

- **運営者が利用者のキーを復号できること自体を、招待の相手が受け入れなくなったとき**。
  外部の鍵管理サービスか、利用者の端末で暗号化する形へ移す。
- **暗号化の鍵が漏れ、原因が環境変数という置き場にあったとき**。
  回転の手順でキーを守ったうえで、鍵の置き場を決め直す。
- **実行環境を、環境変数に秘密を置けない環境へ移すとき**。
  決定 5 を決め直す。
- **二つ目のプロバイダを足したとき**（0043 決定 11 が動いたとき）。
  キーの形式と、利用者一人が複数のキーを持つかを決め直す。
- **回転の頻度が上がり、暗号化し直す手順が重くなったとき**。
  暗号化し直す処理の自動化か、データの鍵を別の鍵で暗号化する二段の形を検討する。
