# 0023. 申し送りの層（`NEXT.md`）を畳む

- **状態**: 採用
- **決定日**: 2026-09-01
- **関係する ADR**: 0014

## 文脈

`NEXT.md` はセッションを跨ぐ申し送りの置き場として立ち上げ時から在り、0014 で追跡から外した。
`ROADMAP.md` の分担表は「開いている issue 番号・申し送り」を持つ層と定め、`CLAUDE.md` はセッション開始時に読む一歩目に置いていた。

2026-09-01 に中身を数えたところ、**24 節 154 行のうち、この層でなければ持てない事実は 2 節だけ**だった。

| 区分 | 節数 | 正を持っているのは |
|---|---|---|
| 状態の写し | 11 | GitHub Issues / PR |
| 決定・経緯の写し | 5 | `docs/adr/` `DEPLOY.md` `HARNESS.md` |
| 規律の写し | 2 | `ROADMAP.md`・並行判定の手順 |
| L5 の宿題 | 2 | issue #56 / #8 の「人間の判定」節 |
| どこにも無い | 2 | `NEXT.md` だけ |

**写しは腐っていた。**
同日の実測で、「PR が 4 本 open」（実際は 0 本）、「#65 の決定は PR #134 に出ている（未マージ）」（8/31 にマージ済み）、「#138 と #120 が `claude.ts` を取り合う」（0021 で `claude.ts` は消えた）、`"event":"claude_call"`（`ai_call` へ改まっていた）。
最終更新は 8/31 21:55 で、9/1 に入った 6 本の PR がどれも反映されていない。

規約の側にも矛盾が二つ残っていた。
`ROADMAP.md` の横断規約は「セッション終了時: 開いている issue 番号を `NEXT.md` に反映 → コミット」と書いているが、0014 で追跡外になったので実行できない。
書式の正典は書き込みを専用ツール経由に限っているが、そのツールはこのリポジトリに無いので、規約どおりに書く手段が最初から無い。

## 決定

`NEXT.md` を削除し、**申し送りの層を持たない**。

- 状態の正は GitHub Issues、順序と横断規約の正は `ROADMAP.md`、決定の正は `docs/adr/`。
  この三つの外に層を作らない
- 現在地の一枚が要るときは、その三つから毎回取り直して派生ビューを作る。
  写しを手で保守しない
- この層でしか持てなかった手元固有の事実は `CLAUDE.local.md` へ移す（0014 が「手元の生態系との接続は一枚へ集める」と決めた原則の延長）
- L5 の宿題は対応する issue の「人間の判定」節が既に持っている

## 理由

**状態を持たない約束が守られないのは、書き手の怠慢ではなく層の性質である。**
毎セッションの終わりに「書いておこう」が働き、そのとき最も新しい事実は状態なので、状態が入る。
入った状態は次のセッションが更新しない限り腐る。
削っても器を残せば同じ力がまた働くので、削るのでなく畳む。

**追跡外であることが、腐りを検出不能にしていた。**
`git diff` に出ず、PR のレビューも通らず、リモートのセッションからも見えない。
写しが本体からずれても、誰も気付く経路が無い。

**「現在地」の役は、取り直せる派生ビューが引き取れる。**
`gh` から毎回取り直す一枚は構造的に腐らない。
手で保守する写しがそれと同じ仕事をする理由が無くなった。

**採らなかった案**——**中身を削って 20 行に縮める**。
腐った 20 節は誰かが意図して足したのでなく、上の力が積み上げた結果なので、器を残せば同じ形へ戻る。
**専用ツールを配って規約どおり書けるようにする**のも採らない。
ツールが解くのは並行追記の競合であって、状態が入り込むことではない。

## 帰結

- セッション開始時に読む一歩目が無くなる。
  続きは issue の一覧から拾う
- worktree へ持ち込むファイルが無くなった（`.worktreeinclude` は entries を持たず、コピーしない理由の記録だけを残す）
- 手元固有の事実が `CLAUDE.local.md` へ集まる。
  あのファイルも追跡外なので、同じ腐り方をしうる。
  違うのは、あちらが持つのが状態でなく接続の指示である点で、接続は状態ほど速く動かない
- リポジトリを clone しても失われる情報が減った

## 覆る条件

- issue にも ADR にも置けない事実が繰り返し発生し、`CLAUDE.local.md` の一枚では捌けなくなったら、置き場を作り直す。
  そのときは状態を持たせない仕組みを層と一緒に決める（規約の文だけでは守られないことが、この決定の根拠である）
