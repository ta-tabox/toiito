# 前の段を前提にする issue の列をスタック型 PR で進め、積み直しは main 以外への force-with-lease で行う

- **状態**: 採用
- **決定日**: 2026-11-02
- **関係する ADR**: なし

## 文脈

#64（ペルソナのテーブル化）と #70（利用者ごとのモデルと API キー）の子 issue は、前の段の表と repo 関数を前提にする列になっている。
「1 セッション = 1 PR」では、後ろの段を前の段のマージ前に書けない。

## 決定

1. 列は 1 issue 1 PR で積み、各 PR のベースを一つ下の段のブランチにする
2. CI の `check` は、ベースを問わずすべての PR で走らせる
3. 積み直しは rebase で行い、main 以外の名前付きブランチへの `--force-with-lease` は Claude が訊かずに叩いてよい
4. main へのマージは下の段から一つずつ、毎回人間が判断する

## 理由

- 各 PR の差分が一段分に収まる
- merge コミットで積み直すと、下の段が動くたびに上の段すべてに取り込みのコミットが増える
- lease は他者が後から push した ref を上書きせずに失敗する

採らなかった案:

- **列を一つの PR にまとめる**
  レビューの単位が列全体になる
- **merge コミットで積み直す**
  複数人で同じスタックへ push するなら採る

## 帰結

- `docs/ROADMAP.md` の横断規約が「1 セッション = 1 スタック」になる
- `check.yml` の pull_request がベースを絞らなくなる
- `guard-force-push.sh` が main 以外への lease 付き push を人間に回さなくなる

## 覆る条件

- 一つのスタックへ複数の人やセッションが push するようになったら
- GitHub のスタック機能が有効になり、積み直しを GitHub が行うようになったら
