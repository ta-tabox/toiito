# アクセシビリティの自動検査の違反を、除外の一覧に無いかぎり E2E の失敗にする

- **状態**: 採用
- **決定日**: 2026-11-14
- **関係する ADR**: 20261113-crisis-utterance-response

## 文脈

検査の連鎖は型・lint・単体テスト・ビルド・E2E で、コントラスト・ラベル・フォーカスの順を見る検査を持たない。
#365（E2E にアクセシビリティの自動検査を足す）は、axe（ブラウザの DOM に当てるアクセシビリティの検査器）を E2E の spec から各画面へ当てる。
axe が見つけた違反を、CI を止める条件にするか、報告に留めるかを決める必要がある。

20261113-crisis-utterance-response は、対話画面の入力欄の下に、彩度を持たない一行の相談窓口の案内を常に出すと決めた。
この案内は危機にある利用者が読む文なので、色のトークンの変更で読めなくなると、決定の目的が失われる。

開発者と判定者は人間 1 人である。

| 案 | 違反の扱い | 直さない違反の扱い |
|---|---|---|
| 赤にする | すべて E2E の失敗 | 理由を添えて除外の一覧に書いたものだけ通る |
| 重大度で分ける | axe の impact が critical と serious のものだけ失敗 | moderate と minor はレポートに出るだけ |
| 報告だけ | 失敗にしない | レポートに出るだけ |

## 決定

1. axe の違反は、除外の一覧に無いかぎり E2E の失敗にする
2. 除外の一覧は spec の側に置き、一行ごとに直さない理由を書く
3. 重大度で失敗と報告を分けない

## 理由

- 判定者が 1 人なので、報告だけの結果は読まれずに積もる
- 直せない違反は除外の一覧へ理由と一緒に足せば E2E が通るので、失敗にしても PR が止まり続けない
- 相談窓口の案内のコントラストを、色のトークンを変える PR の時点で止められる
- 重大度で分ける案を採らなかった条件: axe の impact は規則ごとの既定値で、このアプリの画面にとっての重さを表さない
- 報告だけの案を採らなかった条件: 報告を読む工程が誰の作業にも入っていない

## 帰結

- 画面へ触る PR は、axe の違反を直すか、除外の一覧へ理由と一緒に足すかを選ぶことになる
- E2E のジョブが必須のチェックでないあいだは、失敗してもマージは止まらない
  必須のチェックにするかは #363（E2E を CI で実行）と、ブランチ保護を持つ人間が決める
- 当てる規則の集合（WCAG 2.2 の A と AA のどこまでか）は spec が持つ

## 覆る条件

- 除外の一覧が、直す見込みの無い違反で埋まり、新しい違反を見つける役に立たなくなったとき
- axe の誤検知で失敗する PR が続き、除外の一覧へ足す作業が違反を直す作業より多くなったとき
- 判定者が増え、報告を読む工程を誰かの作業に置けるようになったとき
