# 0045. キーを登録していない利用者は、運営のキーでアプリの既定モデルを使う

- **状態**: 採用
- **決定日**: 2026-09-15
- **関係する ADR**: 0018, 0026, 0042, 0043, 0044

## 文脈

0043 はモデルと API キーを利用者ごとに解決すると決め、0044 は利用者のキーの置き場を決めた。
残るのは、キーを登録していない利用者の AI 呼び出しをどう扱うかである。

| 事実 | 出所 |
|---|---|
| AI の費用は運営のキーに乗っている | #70（ユーザーごとのモデル選択と API キー（BYOK））の目的 |
| 招待制で、決済・広告・寄付の募集を置かない | ADR 0018 決定 2・4 |
| 公開登録を採らなかった条件は、費用を止める手段（#69（管理機能））も利用者のキーへ移す手段（#70）も無いことだった | ADR 0018 の理由節 |
| 「#69 と #70 が入ったら公開登録を選択肢へ戻す」が覆る条件に置かれている | ADR 0018 の覆る条件 |
| 費用が運営に乗るので、既定を安いモデルにすることが求められている | #70 の目的 |

## 決定

1. **キーを登録していない利用者の AI 呼び出しは、運営のキーで行う。**
2. **運営のキーで呼ぶときのモデルは、アプリの既定モデルに限る。**
   利用者のモデルの選択が効くのは、利用者のキーで呼ぶときだけである。
3. **アプリの既定モデルとアプリ全体の深さ（0043 決定 10）は、運営が負担できる費用に収まる安い設定に保つ。**
4. **AI 呼び出しの利用量の記録は、使ったキーの出所（運営のキーか利用者のキーか）を持つ。**

決定時点の例として、既定モデルは `claude-sonnet-5` のまま、アプリ全体の深さを下げる。
既定モデルと深さの現況は `web/README.md` が持つ。
利用量を記録する表は #69 が作る。

## 理由

- **運営のキーで動かす**: キーを持たない相手も招待の時点で使い始められ、自分のキーで高いモデルを使うことは利用者の任意の選択として残る。
- **運営のキーのときは既定モデルに限る**: 利用者が高いモデルを選べると、その費用が運営に乗り、既定を安く保つ意味が無くなる。
- **既定を安く保つ**: キーを登録していない全員の分の費用が運営に乗る。
- **決定時点の例で、モデルを変えずに深さを下げた**: 環境変数だけで変わり、プロバイダの実装に分岐が要らない。
  深さを下げると応答の質が変わりうるので、質は実キーで人間が判定する（0026 は深さを下げることを質との取引と書いている）。
- **キーの出所を記録する**: 運営の費用に乗る呼び出しと利用者の費用に乗る呼び出しを分けないと、利用量の記録から運営の費用を読めない。

採らなかった案。

- **キーの登録を必須にする**: 本番に運営のキーが要らなくなり、費用も運営に乗らないが、招待した相手は登録するまで対話できず、運営者自身もキーを登録することになる。
- **許可した利用者だけに運営のキーを使わせる**: 費用を乗せる相手を絞れるが、サインインの許可リストとは別の一覧を環境変数に持つことになる。
- **運営のキーでも利用者にモデルを選ばせる**: 利用者の選択で運営の費用が上がる。
- **既定モデルを一段安いモデルへ替える**（決定時点の例は `claude-haiku-4-5`）: 価格は下がるが、決定時点の Claude API の文書ではそのモデルは深さの指定を受け付けないので、深さを送らない分岐がプロバイダの実装に要り、扱える文脈の長さも短くなる。

## 帰結

| 対象 | 変わること |
|---|---|
| 本番の運営のキー | キーを登録していない利用者がいる限り、必須のまま残る |
| 運営の費用の上限 | 運営のキーに乗る費用を止める手段は、#69 の停止と #150（外周の守りを決める）のレート制限に残る |
| ADR 0018 の覆る条件 | #70 が入っても、費用を運営から外すかは利用者の任意に留まる。公開登録を選択肢へ戻す判断は、運営のキーに乗る費用を #69 の停止と #150 のレート制限で止められるかで見ることになる。0018 の決定は動かないので supersede しない |
| 利用量の記録（#69） | キーの出所の列が加わる |
| 深さの既定値 | 決定時点の例に合わせて下がる |
| 人間の判定 | 実キーで、既定の設定と利用者が選んだモデルの応答の差が問いの深まりに効くかを見る |

## 覆る条件

- **運営のキーに乗る費用が、運営の負担できる額を超えたとき**。
  キーの登録を必須にするか、運営のキーを使える利用者を絞る。
- **公開登録を開くとき**（ADR 0018 の覆る条件）。
  誰でも運営のキーを使える状態になるので、決定 1 を先に見直す。
- **安く保った設定では問いが深まらないと、実キーで人間が判定したとき**。
  決定 3 の例を選び直す。
- **キーを持たない利用者が、既定以外のモデルを使いたいと求めたとき**。
  決定 2 を見直す。
- **有償化するとき**（ADR 0018 の覆る条件）。
  費用を利用者に移す手段が決済に替わるので、決定 1 を見直す。
