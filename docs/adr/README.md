# ADR — 決定と経緯の受け皿

この器の決定は、1決定1レコードでここに置く。
`ARCHITECTURE.md` が持つのは**現況**、`ROADMAP.md` が持つのは**順序**、
`HARNESS.md` が持つのは**検証**で、**なぜそう決めたか**を持つのはここだけ。

## 規約

1. **1ファイル1決定**。命名は `NNNN-<slug>.md`（4桁ゼロ埋め・連番・欠番を作らない）
2. **ヘッダ**: `状態`（`採用` / `supersede 済み（→ NNNN）`）・`決定日`・`関係する ADR`
3. **節は 文脈 / 決定 / 理由（採らなかった案と、それを採らなかった条件）/ 帰結 / 覆る条件**
4. **書き換えない。** 覆すときは新しい ADR を書き、旧 ADR のヘッダに
   `supersede 済み（→ NNNN）` を足すだけ（**本文は一字も削らない**）
5. **「決定」と読めない事柄は ADR にしない。**
   未決の論点は issue、順序は `ROADMAP.md`、現況は `ARCHITECTURE.md`

`関係する ADR` に入れるのは ADR 番号だけ。
他の文書を指したいときは本文中で参照する（欄の意味を一意に保つと、supersede の連鎖を
機械的に辿れる）。

**`覆る条件` を空にしない。**
ここが書けない決定は、覆るときに誰も気付かないので、採用のまま永久に残る。
書こうとして書けないなら、それは決定ではなく既定の踏襲なので、規約5に照らして
ADR にしない側へ倒す。

## 雛形

```markdown
# NNNN. 決定を一行で

- **状態**: 採用
- **決定日**: YYYY-MM-DD
- **関係する ADR**: なし

## 文脈

何が問題で、なぜ今決める必要があるのか。

## 決定

何を決めたか。

## 理由

なぜそれを選んだか。
**採らなかった案と、それを採らなかった条件**を併記する
（条件が変われば覆るので、下の「覆る条件」と対になる）。

## 帰結

この決定を受けて何が変わるか。波及先。

## 覆る条件

何が起きたらこの決定を見直すか。
```

## ADR にしないもの

（決定というより既定の踏襲で、結論だけを `ARCHITECTURE.md` 等へ置いたものをここに列挙する。
書かないと「なぜ ADR が無いのか」を次のセッションが毎回問い直す）

- **ステップ一覧 S0〜S6 と、その進め方の横断規約**（2026-07-13 起草の `PLAN.md` 由来）。
  順序と契約であって決定ではないので、`ROADMAP.md`（順序）・`CODING.md`（規約）・`HARNESS.md`（検証）が既に持つ
- **当時の完了記録**（S0 / S0b / ハーネス P0 / 立ち上げ / ローカル完結化）。
  履歴であって決定ではない。
  何がいつ完了したかは git 履歴と閉じた issue が持つ
- **S5（AI 応答のストリーミング化）を体感判定で見送る**（2026-07-17）。
  根拠が一往復の体感一回だけで、採らなかった案の条件が立たない。
  そもそも同日中に「実施する」へ改定されているので決定として残っていない。
  ストリーミングの現況は #9（spike）/ #10（実装）と 0002 の帰結節が持つ
- **発話周期の固定に対する「観測手段を先に立てる」**（2026-07-20）。
  何を先にやるかという順序の判断である。
  診断の原文ごと #8（発話周期の可変化）が持つ
- **Vercel Authentication を Standard Protection のまま有効にしておく**（2026-08-28 決定・2026-08-29 に位置づけを訂正・#90（本番環境へデプロイする））。
  Hobby で選べるのはこれだけで、All Deployments は Pro の Advanced Deployment Protection（月 150 ドル）が要る。
  そして 2026-08-29 の実測で、**Standard Protection は本番の URL を守らない**ことが分かった（守るのは production のデプロイ URL と Preview だけで、`<project>.vercel.app` は素通し）。
  **本番のアクセス制限はアプリ側の Basic 認証が持つ**（0013）ので、これは残る二つ——デプロイ URL と Preview——を守るためだけに有効なままにしてある。
  無効化しない理由がそれで、決定というより据え置きになる。
  現況は `DEPLOY.md`
- **独自ドメインを当てない**（2026-08-28・#90（本番環境へデプロイする））。
  何もしないという選択なので、覆る条件が「当てたくなったら」以上に書けない（規約5）。
  当てる時期の見立ては `DEPLOY.md`
- **本番のリージョンを Vercel と Neon の既定で揃える**（2026-08-29・#90（本番環境へデプロイする））。
  `iad1`（Vercel）と AWS US East 1（Neon）。
  日本から見ればシンガポール側が往復で 80ms ほど近いが、`ARCHITECTURE.md`「意図的にやらないこと」の摩擦／妨害の切り分けに照らすと妨害ではない。
  体感を決めているのは Neon の Scale to Zero からの復帰時間で、そちらが未実測である。
  実測して復帰が速く 170ms の方が気になるなら、Vercel の `regions` と Neon のプロジェクトをまとめてシンガポールへ動かす。
  **片方だけ動かすと毎クエリが太平洋を渡る**ので、動かすなら必ず両方
- **Node と `@types/node` を 24 系に据え置く**（2026-08-29・#98（依存とランタイムの版を揃え直す））。
  Node 26 の LTS 入りを待つだけなので、決定ではなく予定の踏襲である。
  覆る条件も「26 が LTS になったら」以上に書けない（規約5）。
  版の正は `mise.toml` で、`@types/node` はランタイムに従属する
- **本番の接続文字列を `sslmode=verify-full` で終える**（2026-08-29・#105（本番の接続文字列を `sslmode=verify-full` にする））。
  `pg` はいま `require` を `verify-full` と同じ強度で扱っているが、v9 で libpq の意味へ変わって証明書を検証しなくなる。
  明示は現在の振る舞いを版の変化から切り離すだけで、**選択肢の間で選んだわけではない**（`pg` 自身が警告文で指示している綴りでもある）。
  覆る条件も「Neon が `verify-full` を通さなくなったら」以上に書けない（規約5）。
  `uselibpqcompat=true&sslmode=require` は代替案ではなく、Neon がこの綴りを通さなかったときの倒し先として控えていたものである（意味を libpq へ寄せるだけで強度は上がらない）。
  本番の値を触る前に確かめたところ、Neon は直結・プーラーのどちらのホストでも通したので、倒し先は使わなかった。
  確かめ方は、当てずっぽうの資格情報を `pg` 8.23.0 から投げること——証明書の検証は TLS の握手の中で終わり、パスワードの照合はその後なので、認証エラー（28P01）が返れば TLS を抜けた証拠になる。
  現況は `DEPLOY.md`「秘密の置き場」
- **他人へ開くにあたって、ホスティングと本番 DB を据え置く**（2026-08-30・#65（認証と所有権の方式を決める））。
  Vercel Hobby と Neon Free のままにする。
  ADR 0002 の覆る条件は「他人へ開いて**収益化**する段」で、0018 が無償の招待制に決めた以上そこは発火しない。
  Vercel の fair use が商用と呼ぶのは "financial gain"——決済・広告・アフィリエイト・制作や運用への報酬・寄付の募集——であって、利用者の数ではない（2026-08-30 に原文で確認）。
  つまりこれは選択肢の間で選んだのではなく、覆る条件に当たらないことを確かめただけである。
  読みの確定そのものは 0018 の帰結節が持つ
