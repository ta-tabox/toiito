# 0012. Neon は Vercel Marketplace 経由で作らず、自分の組織の下に置く

- **状態**: 採用
- **決定日**: 2026-08-29
- **関係する ADR**: 0002

## 文脈

ADR 0002（本番の実行環境を Vercel にする）で実行環境が決まり、DB は Neon で決着している。
Neon を Vercel へ紐づける経路は二つある。
Vercel Marketplace から入れる Vercel-Managed と、Neon 側にアカウントを持つ Neon-Managed である。

このアカウントには前のテストアプリで作った `Vercel: ta-tabox` という組織が既にあり、そこへ相乗りできる状態だった。

ADR 0002 の禁止則「Vercel 固有の口をアプリへ入れない」はアプリのコードを対象にしているので、この選択はそこに掛からない。
どちらを採ってもアプリは `DATABASE_URL` と `DIRECT_URL` を読むだけで、コードは一行も変わらない。

## 決定

Neon 側で自分の組織を切り、その下に本番プロジェクトを作る。
Vercel Marketplace の Neon 統合は使わない。
Vercel には環境変数 3 本を手で入れる。

## 理由

剥がすときが片側で済む。
ADR 0002 は Vercel を離れる条件を三つ挙げているが、Marketplace 経由だとそのとき DB の所有権も動かすことになる。
**Vercel-Managed から Neon 直接への移管にはセルフサービスの経路が無い**（2026-08-29 に Neon のドキュメントで確認）。
手仕舞い（このプロジェクトは終わる）でも、閉じる相手が一つ増える。

**Vercel-Managed を採らなかった条件**: 上の移管の重さである。
自動配線が節約するのは実質 1 本だけで、対価に釣り合わない。
統合が注入するのは `DATABASE_URL`（プーラー）と `DATABASE_URL_UNPOOLED`（直結）だが、この器の `prisma.config.ts` が読むのは `DIRECT_URL` なので、名前が合うのは前者しかない。

**`prisma.config.ts` を `DATABASE_URL_UNPOOLED` へ寄せる案を採らなかった条件**: 環境の都合でリポジトリを変えることになる。
ADR 0002 が Fly.io を落とした条件がまさにこれで、同じ形を自分から作ることになる。

**既存の `Vercel: ta-tabox` 組織へ相乗りする案を採らなかった条件**: 所有権に加えて、無料枠を食い合う。
Neon の Free は 100 compute hours が組織あたりで、0.5 GB ストレージと 5 GB 転送がプロジェクトあたりである（2026-08-29 に作成画面で確認）。
テストアプリと同じ組織に置くと compute を分け合うことになる。

**テストプロジェクト `neon-green-grass` を流用する案を採らなかった条件**: ストレージと転送がプロジェクト単位の枠なので食い合う。
それ以前に、テスト用のデータと自分の問いが同じ DB へ同居する。

## 帰結

- `DEPLOY.md`「初回のセットアップ」の手順 1 が、組織の切り方まで指す
- Vercel の環境変数 3 本は手で入れる。
  Marketplace の統合を入れないので、自動では現れない
- 課金の相手が Vercel と Neon の二つに分かれる。
  どちらも無料枠の内側にいる限り請求は立たない

## 覆る条件

- 有料プランへ上がる段で、請求書を一つに寄せたくなったら。
  そのとき所有権のコストと事務のコストを比べ直す
- Neon が Vercel-Managed から Neon 直接への移管にセルフサービスの経路を作ったら。
  剥がすコストが消えるので、この決定の主な理由が無くなる
- 実行環境を Vercel から動かしたら。
  Marketplace という選択肢自体が消える
