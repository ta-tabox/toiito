# 0028. 器自身の文書を `docs/` へ寄せ、`DESIGN.md` を規範と記述に分ける

- **状態**: 採用
- **決定日**: 2026-09-06
- **関係する ADR**: 0027

## 文脈

0027 は `CODING.md` を `.claude/rules/` へ移したが、ルートに残る 6 本（`VISION.md`・`ARCHITECTURE.md`・`HARNESS.md`・`ROADMAP.md`・`DEPLOY.md`・`DESIGN.md`）の置き場と、`DESIGN.md` を規範と記述へ割るかどうかは「別の作業単位」として切り出していた。
参照が ADR の外に百箇所あり、一度に動かすとレビューで移動と書き換えが混ざるためである。

雛形（`fermentary/playbooks/terrarium.md`「文書の層」）は「ルートに置くのは道具がそのパスを決め打ちで読むファイルだけ」へ改まっており、coten-atlas は ADR-0032・0033 で同じ形へ揃えている。
この器だけが雛形と違う位置に留まっている。

## 決定

- **ルートに置く条件は「道具がそのパスを決め打ちで読むか」の一点にする。**
  残るのは `README.md`（GitHub）・`LICENSE`・`CLAUDE.md` と `CLAUDE.local.md`（Claude Code）・`compose.yaml`（docker compose）・`mise.toml`（mise）と、`.claude/`・`.github/`・`docker/`・`extensions/`・`web/`。
  器自身の文書 6 本は `docs/` へ移す
- **`docs/` の中をディレクトリで割らない。**
  下位に立つのは `adr/` だけにする
- **`DESIGN.md` を規範と記述へ分ける。**
  判定は節の見出しでなく文の単位で行い、基準は**その文に違反が書けるか**。
  違反が書ける文は `.claude/rules/design.md`（`paths` は `web/src/**/*.{tsx,css}`）へ、値と現況は `docs/DESIGN.md` へ残す
- **雛形の `design.md` は骨格として使わない**

## 理由

道具が決め打ちで読むファイルは移すと壊れるので、ルートに置く条件はそこで尽きる。
移せるものを残す理由は「ルートの `ls` が目次として働く」だけだったが、6 本を集めた `docs/` の `ls` が同じ働きをするので、条件として立たない。

`docs/` を割らないのは、層（なぜ / どう / どう見えるか / 検証 / 順序 / 決定）を `CLAUDE.md`「正はどこにあるか」と各文書の冒頭が既に持っているためである。
ディレクトリで二重に表すと同じ層が二箇所に書かれ、片方だけが動く。
件数で増えるのは `adr/` だけで、残る 5 本は器が終わるまで 5 本のままなので、階層を作っても探す側が当てる手間が増えるだけになる。

**「違反が書けるか」は文の単位でしか効かない。**
「面は彩度を持たない」は破れる（彩度のある面を三つ目に足せる）ので規範だが、「地は `#fbf9f4`」は破りようがなく参照するだけなので記述である。
見出し単位で割る案を採らなかったのは、同じ節の中で表が記述・規律が規範に割れる節があったからで、「話者の描き分け」（表は値、温度と枠で分ける規律は規範）と「状態の見せ方」（7 値の表は値、7 値を色で分けないは禁止則）の二つがそれに当たる。
見出しごと `docs/` へ落とすと、守らせたい禁止則が守らせる側から消える。

雛形の `design.md` は見出しと括弧の穴埋めだけを持つ骨格で、この器は 297 行の本文を既に持っている。
雛形の見出し（トークン / レイアウト / コンポーネント / 文言 / アクセシビリティ）はこの器の節と対応せず、`web/src` のコメント 15 箇所が節名で規範を指しているので、雛形の見出しへ組み替えると参照が全部切れる。
`paths` も雛形は全 UI 拡張子を対象にするが、この器のコードは `web/src` に閉じている。

## 帰結

- ルート直下の md は `README.md`・`CLAUDE.md`・`CLAUDE.local.md` の 3 本になる
- 0027 までのレコードが名指す 6 本は `docs/` 直下と読み替える（規約4により本文は書き換えず、`docs/adr/README.md` が読み替えを持つ）
- `.claude/rules/` は `writing.md`・`coding.md`・`design.md`・`languages/typescript.md` の 4 本になる
- `.claude/rules/design.md` は 136 行で、issue #181（器自身の文書を docs/ へ寄せる）が置いた 100 行の目安を超えた。
  値を一つも持たず、占めているのが規則とその根拠だけなので、`docs/` へ戻せる説明が残っていない
- 適用済みの `web/prisma/migrations/20260816090000_init/migration.sql` だけは `HARNESS.md` の名指しを残す。
  Prisma が checksum で本文を見張っており、書き換えると流し直しが止まる

## 覆る条件

`docs/` の直下が 10 本を超え、層でなく件数で探すことになったとき。
そのときは層でなく件数の多い種別を下位へ落とす（`adr/` と同じ理由づけになる）。

`.claude/rules/design.md` だけで UI を書けず、値を見に `docs/DESIGN.md` を開く回数が多いとき。
境界が規範の側へ寄りすぎているので、閾値を持つ規則（16px・1.9・8px の倍数）ごと `docs/` へ戻し、rules は禁止則だけにする。

Claude Code が `.claude/rules/` の `paths` を廃止したとき（0027 の覆る条件と共通）。
