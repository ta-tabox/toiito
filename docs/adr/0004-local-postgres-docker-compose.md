# 0004. ローカルの Postgres は Docker Compose で立てる

- **状態**: 採用
- **決定日**: 2026-08-15
- **関係する ADR**: 0003

## 文脈

0003 で開発も本番も Postgres 一本にすると決めた結果、手元で Postgres をどう立てるかを決める必要が出た。
置き場と ORM（Neon + Prisma 7）は hatchery の kb `postgres-hosting-selection-2026.md` が正典なので、この器で決めるのはローカルの立て方だけである。

## 決定

ローカルの Postgres は Docker Compose で立てる。
起動の手順と接続文字列の置き場は `HARNESS.md` が持つ。

## 理由

本番の Neon と同じ本物の Postgres が立つので方言差が出ず、CI でも同じ手が使えるためである。
開発・CI・本番の三箇所で同じ方言を踏むことが 0003 の目的そのものなので、ローカルだけ別物にすると転換の意味が薄れる。

**`prisma dev` を採らなかった条件**: Docker が要らないのは利点だが、立つのは本物の Postgres サーバではない。
CI で結局別手段が要ることになり、「同じ手が使える」という決め手が消える。

## 帰結

- 開発の起動手順にルートでの `docker compose up -d` が入った（`CLAUDE.md` の開発ハーネス節・`HARNESS.md`）
- 0003 で引き受けた「起動に外部プロセスが要る」の実体がこれになった
- CI も同じ Postgres コンテナで立てられるので、テストの前提をローカルと揃えられる

## 覆る条件

- **`prisma dev` が本物の Postgres サーバを立てるようになったら**。
  採らなかった唯一の条件が消えるので、Docker の要らない側へ倒れる
- **CI をローカルと別の手で立てることになったら**。
  「同じ手が使える」が決め手だったので、そこが崩れれば選び直しになる
- **Docker が使えない環境で開発することになったら**。
  ローカル完結性は 0003 で既に捨てているので、代わりに何を立てるかだけを決め直す
