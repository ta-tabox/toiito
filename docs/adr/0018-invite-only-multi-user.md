# 0018. 自分専用という運用前提を改め、招待制で他人へ開く

- **状態**: 採用
- **決定日**: 2026-08-30
- **関係する ADR**: 0002, 0013

## 文脈

`ARCHITECTURE.md`「意図的にやらないこと」は「マルチユーザー対応の作り込み（自分専用。Auth は門としてのみ）」を挙げていた。
この一行が第二波の四本——#68（ログインと所有権）・#69（管理機能）・#70（BYOK）・#64（ペルソナをテーブルへ）——の前に立っている。
改めないまま実装へ進めば、規約違反のまま進むことになる。

MVP は 2026-08-30 に到達と判定され（#7（MVP 到達判定・常用開始））、常用が始まっている。
本番も 2026-08-29 に立ち、Basic 認証の門が掛かった（0013）。
門は通すか通さないかしか決めないので、複数の人間を区別できない。

## 決定

1. **他人にも使わせる器へ改める。**
   VISION の「自分の問いと向き合う」という設計原理は動かさない。
   動くのは「自分専用」という運用前提だけである。
2. **開き方は招待制。**
   許可リストに載ったメールアドレスだけが入れる。
   公開登録は開けない。
3. **許可リストは環境変数のメール一覧で持つ。**
   DB のテーブルにも招待の UI にもしない。
4. **無償で提供する。**
   決済・広告・寄付の募集を置かない。
5. **捨てアカウント枠（Google を使わずに入れる口）は、いまは入れない。**
   #133（Google を持たない相手のための、捨てアカウント枠を足す）として立てておき、要求が実際に出た回に方式から決める。

## 理由

**公開登録を採らなかった条件**: AI の費用がアプリ側に乗っており、止める手（#69（管理機能））も自分のキーへ逃がす手（#70（BYOK））もまだ無い。
URL を知っている誰でも `ANTHROPIC_API_KEY` で課金を走らせられる状態は、0013 が本番で一度踏んだ形そのものである。
二本が入れば公開は選択肢へ戻るが、所有権の実装（#68（ログインと所有権））は招待制でも公開でも同じなので、**先に絞っておくことに手戻りが無い**。

**個人用のまま保つ案を採らなかった条件**: 他人に使わせたいという要求が先にあり、それが #65（認証と所有権の方式を決める）の目的そのものである。
加えて #64（ペルソナをテーブルへ）は利用者ごとの複製を、#75（ペルソナの記憶）はその持ち主を要求している。
個人用のままだと、この二本が前提を失う。

**anonymous を採らなかった条件**: 招待は宛先を要求し、anonymous は識別子を持たない。
許可リストで絞る手段が無いので、開けた時点で実質的に公開になる。
決定 2 と構造的に両立しない。

**magic link / email OTP をいまは採らなかった条件**: どちらもメールアドレスが識別子になるので招待制とは両立するが、メール送信基盤が依存として増える。
手仕舞い（このプロジェクトは終わる）で閉じる相手が一つ増える形で、これは 0012 が Vercel Marketplace の Neon を落とした理由と同型である。
招待制なら宛先は既に分かっているので、いま払う理由が無い。

**DB の招待テーブルを採らなかった条件**: 招待の発行・失効・取り消しの UI が #68（ログインと所有権）へ乗り、#69（管理機能）と重なる。
数名の許可リストに、その面積は釣り合わない。
人を足すのに再デプロイが要るのは対価だが、招待が数回しか起きないなら痛まない。

**有償化を採らなかった条件**: Vercel Hobby の fair use は商用利用を "any Deployment that is used for the purpose of financial gain of anyone involved in any part of the production" と定義し、決済・広告・アフィリエイト・制作や運用への報酬・**寄付の募集**を列挙している（2026-08-30 に原文で確認）。
無償で他人に使わせることは、どれにも当たらない。
有償化した日に、実行環境の決め直し（0002 の覆る条件）が同時に来る。

## 帰結

- `ARCHITECTURE.md`「意図的にやらないこと」から「マルチユーザー対応の作り込み」の行が落ち、代わりに「公開登録」と「パスワード認証」の二行が入る
- **ADR 0002 は覆らない。**
  覆る条件の一つ目（他人へ開いて収益化する段）の読みが、上の fair use の原文で確定した。
  基準は financial gain であって利用者の数ではないので、無償の招待制はこの条件を発火させない。
  ホスティングと本番 DB は Vercel Hobby + Neon Free の据え置きになる
- **ADR 0013（Basic 認証）は #68（ログインと所有権）が入った回に覆る。**
  覆る条件の一つ目がそのまま満たされる
- #133（捨てアカウント枠）が立ち、`ROADMAP.md` の第二波へ入る
- 本番の環境変数に許可リストの 1 本が増える（`DEPLOY.md`「秘密の置き場」の更新は #68 が持つ）

## 覆る条件

- **#69（管理機能）と #70（BYOK）が入ったら、公開登録を選択肢へ戻す。**
  費用を止める手と逃がす手が揃えば、招待制を保つ理由は薄くなる
- 招待の相手が増えて、環境変数の一覧と再デプロイが窮屈になったら。
  そのとき DB の招待テーブルへ移す
- 収益化する日が来たら。
  決済・広告・寄付の募集のどれかを置いた時点で ADR 0002 の覆る条件が発火する
- Google アカウントを持たない相手を入れる必要が出たら。
  #133（捨てアカウント枠）へ戻る
