# 0041. メモは `keyword` と `note` を直せるようにし、削除は論理削除にする

- **状態**: 採用
- **決定日**: 2026-09-14
- **関係する ADR**: なし

## 文脈

メモの repo 関数は `addMemo`（`web/src/lib/db.ts`）だけで、削除も修正も無い。
誤って付けたメモは、対話画面の下線ごと残り続ける。

`messages` は不変（追記のみ・編集しない）と決めてあり、メモの anchor（発話本文内の文字オフセット `anchor_start`・`anchor_end`）が指す位置がずれないのはこの不変性による（`docs/ARCHITECTURE.md`「メモとアンカー」）。
`memos` 自体を書き換えてよいかは、どの文書でも決めていない。

常用の中で、人間は消したくなったメモと直したくなったメモの両方を持った。

決めるのは次の五つである。

- メモを消せるか、消すなら物理削除か論理削除か
- どの列を直せるか、anchor を動かすか
- 消したメモをどの表示から除き、戻す操作を作るか
- 消す・直す操作をどこに置き、削除の前に確認を挟むか
- 誤ったメモを消せないことが、`docs/DESIGN.md`「残す摩擦」の残す摩擦と直す妨害のどちらに当たるか

## 決定

| 項目 | 決めたこと |
|---|---|
| 分類 | 誤ったメモを消せも直せもしないことは、直す妨害に当たる |
| 削除の方式 | 論理削除。`memos` に `deleted_at` を足し、削除は行を残して時刻を書く |
| 消したメモを除く表示 | すべて（`/memos`・対話画面の下線・セッション切り替えのキーワード） |
| 消したメモを戻す操作 | 作らない |
| 直せる列 | `keyword` と `note` |
| anchor | 動かさない。範囲を誤ったメモは消して付け直す |
| 操作の置き場 | `/memos` の拡大表示（`MemoDialog`）。対話画面には置かない |
| 削除の確認 | 削除の操作の後に確認の一手を挟む |

## 理由

- 誤ったメモの下線は、対話を読み返すたびに問いでなく道具の誤りへ注意を向けるので、`docs/DESIGN.md`「残す摩擦」の線引き（問いへ向かう注意を止めるものは残し、道具そのものへ注意を奪うものは直す）に照らして妨害に当たる
- 行を残せば戻す操作を後から作れ、`memo_links` が書き込まれた後もメモを指す辺の参照先が消えないので、削除は論理削除にする
- 消したいメモを弱い装飾で残すと、その装飾がまた道具へ注意を向けるので、消したメモはすべての表示から除く
- 戻す操作には消したメモを並べて見せる場所が要り、消したいものを別の場所で見せ続けることになるので、戻す操作は作らない
- 戻す操作が無く、誤って消したメモは画面から戻らないので、削除の前に確認の一手を挟む
- `keyword` と `note` は文字列で、入力欄を置くだけで直せるので、直せるようにする
- anchor を選び直すには対話画面で範囲を選択する操作をもう一つ作ることになり、消して付け直せば同じ結果が得られるので、anchor は動かさない
- `/memos` の拡大表示はメモ一件を名指しで開き、`keyword`・`note`・引用を一度に読める画面なので、消す・直す操作はそこに置く
- 対話画面は既定を読みに置いている（`.claude/rules/design.md`「重心」）ので、読み返しの最中に編集の操作を出さないよう、対話画面には置かない

採らなかった案と、それを採らなかった条件。

- **削除も修正も作らない**（メモを不変にする）。
  操作が増えず、`messages` と同じ不変の形にできる。
  誤ったメモが下線ごと残ることが妨害なので採らなかった
- **物理削除**。
  読み取りの関数に条件が増えず、migration も要らない。
  戻す操作を後から作れず、`memo_links` が書き込まれた後は辺の参照先が消えるので採らなかった
- **anchor も選び直せる**。
  範囲の誤りを、メモを消さずに直せる。
  選び直す操作が対話画面に増え、消して付け直すことで同じ結果になるので採らなかった
- **対話画面に消したメモの痕跡を残す**。
  消した事実が読み返しで分かる。
  `.claude/rules/design.md`「彩度の規律」に合う装飾を新しく一つ決めることになり、消したいものが弱い形で残るので採らなかった
- **消したメモを戻す操作を作る**。
  誤削除を戻せる。
  消したメモを見せる場所が要り、誤削除は削除の前の確認で止めるので採らなかった
- **操作を対話画面の下線の覗き見（`web/src/components/memo-preview.tsx`）にも置く**。
  メモを付けた直後にその場で直せる。
  同じ操作が 2 箇所に入り、読み返しの最中に編集の操作が出るので採らなかった
- **確認を挟まない**。
  一手で消せる。
  戻す操作が無く、誤削除が画面から戻らないので採らなかった

## 帰結

- `memos` に `deleted_at` 列が加わり、migration が 1 本入る
- メモを読む repo 関数（`listMemosForSession`・`listMemosWithContext`・`listSessionsWithKeywords`）は、`deleted_at` が null の行だけを返す
- `/memos?memo=<id>` が消したメモを指したとき、`listMemosWithContext` がその行を返さないので、拡大表示は開かない
- 修正は #243（`/memos` の拡大表示からメモの `keyword` と `note` を直す）が作る
- 論理削除は #244（`/memos` の拡大表示からメモを論理削除する）が作る
- `docs/ARCHITECTURE.md`「データモデル」の `memos` に `deleted_at` が加わる。
  現況の文書なので、#244 が実装した回に書き足す
- `messages` の不変性は変わらない。
  anchor を動かさないので、anchor が指す位置がずれない条件もそのまま成り立つ
- `memo_links` を実装するときは、論理削除したメモを指す辺の扱いを決めることになる

## 覆る条件

- 誤って消したメモを戻したくなる回が出たとき。
  戻す操作と、消したメモを見せる場所を作るかを決め直す
- 範囲を誤ったメモを消して付け直す回が繰り返されたとき。
  anchor を選び直す操作を作るかを決め直す
- 対話画面を読んでいる最中に、`/memos` へ移らずにメモを直したくなる回が繰り返されたとき。
  操作を対話画面にも置くかを決め直す
