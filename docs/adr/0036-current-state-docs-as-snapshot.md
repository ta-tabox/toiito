# 0036. 現況の文書はソースコードのスナップショットと同じ時制で書き、経緯を持たない

- **状態**: 採用
- **決定日**: 2026-09-14
- **関係する ADR**: 0023, 0028

## 文脈

`docs/` の md が、冒頭で宣言している持ち場の外の内容を抱えていた。
#198（docs の md を「md の持ち場」で照合し、持ち場でない内容を移す）で全体を計測した。

| 文書 | 行 | 字 | 日付を含む行 | issue 番号の参照 |
|---|---|---|---|---|
| `ARCHITECTURE.md` | 271 | 21,417 | 12 | 6 |
| `ROADMAP.md` | 239 | 20,074 | 12 | 166 |
| `HARNESS.md` | 299 | 23,223 | 5 | 5 |
| `DEPLOY.md` | 404 | 26,145 | 10 | 0 |
| `DESIGN.md` | 190 | 8,175 | 3 | 23 |
| `README.md` | 83 | 5,203 | 0 | 0 |

混入していた形は四つ。

- 見出しに日付が付く（「所有権（2026-08-30 決定）」）
- 実測値に日付と回数が付く（「一往復の実測は 15〜27 秒（2026-08-29・実キー・本番で 2 回）」）
- 閉じた issue の番号が現況として残る（`DESIGN.md`「残す摩擦」の右列 4 件はすべて閉じていた）
- 撤回した順序の理由が撤回の記録ごと残る（`ROADMAP.md`「順序の理由」80 行のうち、open の issue に効く行は十数行）

`README.md` は Basic 認証と「自分専用」を現況として書いていたが、0018 と 0033 で覆っていた。

## 決定

1. **現況の文書は、コードとリポジトリの設定のいまの形だけを書く。**
   対象は `README.md`・`web/README.md`・`docs/ARCHITECTURE.md`・`docs/DESIGN.md`・`docs/HARNESS.md`・`docs/DEPLOY.md`。
   `docs/ROADMAP.md` は open の issue の順序だけを書く
2. **見出しに日付を付けない。実測値は値だけを置き、日付と回数を持たない。**
   例外は「最後に確かめた日付」を値として持つと決めた欄だけ（`HARNESS.md` の ruleset）
3. **issue 番号を現況の文書に置かない。**
   置いてよいのは `ROADMAP.md` の、open の issue の順序の事実だけ
4. **理由は一文まで。二文目からは ADR。**
   ADR が無ければ新しく書き、決定日は元の日にする
5. **決定でも予定でもない出来事の記録は git に任せ、退避先を作らない。**
   撤回した順序の理由・完了の記録・確認の記録がこれに当たる
6. **判定の規則は `.claude/rules/writing.md`「md の持ち場」が持つ。**
   本レコードは決定と理由だけを持つ

## 理由

読み手はこのセッションを見ていないエンジニアで、現況を取り出すのに経緯を読み分けなければならない文書は、その読み手に辞書を要求する。
日付付きの追記は差し替えでなく積み上げになるので、続ければ文書が経緯のログになる（0023 が `NEXT.md` で見た形と同じ）。
ADR が cold 層として在るので、経緯は捨てずに移せる。

採らなかった案と、それを採らなかった条件。

- **各文書に「経緯」節を設ける** — ADR が無いリポジトリなら要る。
  このリポジトリは `docs/adr/` を持つ
- **経緯をすべて ADR へ退避する** — 出来事が決定なら要る。
  撤回した順序や完了の記録は決定ではなく、ADR にすると `docs/adr/README.md` 規約 5 に反する
- **日付を lint で機械検出する** — 再混入が繰り返し止まらないなら要る。
  `HARNESS.md` の確認日のような、値として持つ日付を機械は区別できない

## 帰結

- 経緯のうち決定に当たるものは 0034（原型と `current_form`）と 0035（一方向に閉じた材料）へ割った
- `docs/ARCHITECTURE.md` は「持ち越した開いた問い」節を持たない。
  未決の論点は issue と `docs/VISION.md`「開いた問い」が持つ
- `docs/ROADMAP.md` は MVP の依存グラフと完了条件を持たない。
  閉じた issue の順序は git の履歴が持つ
- `docs/HARNESS.md` は「フェーズ」節を持たない。
  予定だった LLM-as-judge の検査は issue へ移した
- `.claude/rules/writing.md`「md の持ち場」に、現況の文書の判定を足した

## 覆る条件

- 日付や閉じた issue 番号の再混入が PR レビューで繰り返し止まらなくなったら、lint を検討する
- 薄くしすぎて必要な制約まで落ちたと人間が判定したら（#198 の人間の判定）、落ちた制約を現況として書き戻す
