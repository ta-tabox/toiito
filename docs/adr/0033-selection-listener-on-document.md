# 0033. 発話の選択は document のリスナで購読し、終わりの合図に touchend を足す

- **状態**: 採用
- **決定日**: 2026-09-08
- **関係する ADR**: なし

## 文脈

`web/src/components/message-body.tsx` は、発話本文で選んだ範囲からメモの下書きを立てる。
下書きを立てる合図は「選択が終わったこと」で、ブラウザはそれを一つのイベントでは教えない。

素直な実装は本文の `<div>` へ `onMouseUp` を付けることだが、これは実機で二度落ちている。
一つはデスクトップで、本文の途中から下へドラッグするとボタンを離す位置が本文の枠の外になる。
もう一つは iOS で、選択ハンドルを動かして離す一連の終わりに `mouseup` が来ない（#147（スマホで発話を選んでもメモが作れない））。

どこで何を購読するかを決めておかないと、同じ失敗を実装のたびに踏み直す。

## 決定

**選択の購読を `document` に置き、`mouseup` / `touchend` / `keyup` の三つを見る。**

- 発話ごとの読み手（`SelectionReader`）を React の外のレジストリ（`readers`）へ登録する
- `document` へのリスナは `readers` が空でなくなったときに一組だけ張り、空に戻ったときに外す
- 三つのイベントはどれも「選択を読み直せ」の合図として同じ扱いにする

## 理由

**本文の `<div>` へ `onMouseUp` を付ける案を採らなかった条件**: React のハンドラは自分の部分木の外で起きた `mouseup` を受け取らないので、枠の外で離した選択が丸ごと取れない。
加えて、静的な `<div>` へマウスのハンドラを付けること自体を biome が止める（`a11y/noStaticElementInteractions`）。

**発話ごとに `document` のリスナを張る案を採らなかった条件**: 画面には発話が何十件も並ぶ。
一件につき三本張ると、選択のたびに全件が反応する。
レジストリを一つ置けばリスナは一組で済み、始点が入っている発話だけに読み直させられる。

**`keyup` を足した条件**: shift + カーソルキーで伸ばした選択にはマウスもタッチも関わらない。

**`touchend` を足した条件**: iOS は選択のジェスチャの終わりに `mouseup` を撃たない。
長押しから選択ハンドルを動かして離す一連は `touchend` で終わる。
`mouseup` が来るのはただのタップのときだけで、その時点では選択が既に潰れている。

**`pointerup` を採らなかった条件**: 同じ実機で `touchend` が来た回のうち、`pointerup` は半分ほどしか来なかった（#147 の実測）。
一本で両方を賄える見込みが立たなかったので、`touchend` を名指しで足した。

## 帰結

- `message-body.tsx` の `subscribeSelection` は、購読先とイベントの三つ組をこの ADR の実装として持つ。
  JSDoc に残すのはレジストリの張り外しの規則だけで、選んだ理由はこの ADR を指す一行に畳む
- リスナは `document` に居るので、発話の DOM が入れ替わっても購読が切れない
- E2E は実機のジェスチャを再現しないので、`touchend` については「リスナが張られていること」までしか見られない（`web/e2e/memo.spec.ts`）

## 覆る条件

- iOS の Safari が選択のジェスチャの終わりに `pointerup` を安定して撃つようになったら。
  そのとき三つのイベントを `pointerup` + `keyup` の二つへ寄せられる
- 選択からメモを作る入口が、本文の選択以外に増えたら。
  合図が「選択の終わり」でなくなるので、購読の置き場から決め直す
- `document` への購読が別の機能と衝突したら（本文の外で選択を扱う画面が増えたときなど）
