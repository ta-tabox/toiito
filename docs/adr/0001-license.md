# 0001. コードも文書も MIT で覆い、範囲の限定は README が持つ

- **状態**: 採用
- **決定日**: 2026-08-27
- **関係する ADR**: なし

## 文脈

リポジトリは 2026-08-22 に public へ切り替わったが、`LICENSE` を置かないまま公開が先行した。
`gh repo view --json licenseInfo` は `null` を返す。
著作権法の原則どおり全ての権利が留保された状態なので、読む人は再利用の可否を判断できない。
`README.md` も無く、リポジトリを開いた人が何のプロジェクトかを判断する材料も置かれていない。

決めることは三つある。
コードのライセンス、データや文書をコードと分けるか、外部由来の要素をどう扱うか。

## 決定

1. **コードのライセンスは MIT**。
   ルートに標準の本文を一字も変えずに置く。
2. **リポジトリ内の文書もコードと分けない**。
   `VISION.md` 等の設計文書・`web/src/personas/*.md` のプロンプト・`web/scripts/seed/questions.ts` のシード対話は、すべて同じ MIT が覆う。
3. **外部由来は `.claude/skills/karpathy-guidelines/` の一つだけ**で、自分のライセンスの範囲外とする。
   出所と上流の主張は README の「同梱している外部由来のもの」の節が持つ。
4. **範囲の限定は `LICENSE` 本文の外へ書く**。
   持つのは README。

## 理由

**MIT を選んだ理由**: 器の価値はコードの独自性ではなく構成と判断の履歴にあるので、再利用条件は最短で伝わればよい。

**Apache-2.0 を採らなかった条件**: 特許ライセンスの明示と報復条項が主な利得だが、特許が絡む実装が無い。
本文の長さだけが読み手の費用として残る。

**置かないを採らなかった条件**: 全権利留保を意図的に選ぶ道はあるが、GitHub 上では「決めていない」と同じ外形になる。
決定が読み手に届かないので、決めた意味が消える。

**データや文書を CC BY 4.0 へ分けることを採らなかった条件**: 二つある。
一つ目は、この器の独自価値がデータでなく構成と判断の履歴そのものである点。
人手のキュレーション成果が価値の中心を占めるなら帰属表示を要求する意味があるが、ここはそうではない。
二つ目は、**分ける対象がそもそもリポジトリに無い**点——ユーザーの問いとセッションは Postgres にあり、`/data` と `.env*` は gitignore で、追跡下にデータベースのファイルは一つも無い。
分ければ帰属表示を要求できる代わりに、読む・引くときの摩擦が増える。

**範囲の限定を `LICENSE` 本文へ書かない理由**: 除外条項を足すと SPDX として MIT と識別されなくなり、`licenseInfo` が `NOASSERTION` へ倒れうる。
決定を機械が読める形で置くことが目的なので、本文をいじると目的そのものを損なう。

**この決定を ADR だけに書かない理由**: ADR だけが行き先を知っている状態だと、実装のときに台帳を引かないと辿り着けず漏れる。
よって残る作業は #88（ライセンスと README）の本文が持つ。

## 帰結

- ルートに `LICENSE`（標準の MIT 本文）と `README.md` が置かれる
- `gh repo view --json licenseInfo` が `null` を返さなくなる（public なのでその場で打てる）
- 同梱スキルの上流（`multica-ai/andrej-karpathy-skills`）には **LICENSE ファイルが無く**、README 本文が "MIT" と言うだけである。
  再現すべき著作権表示の行が存在しないので、README には出所・ピンしたコミット・上流の主張を記すに留める
- ユーザーの問いとセッションの扱いは、ライセンスでなくプライバシーの問題として別に立つ。
  #68（ログインとリソースの所有権）以降で改めて判じる

## 覆る条件

- 企業がコードを取り込む前提を強く意識する段になったら、特許条項のために Apache-2.0 を再検討する
- ユーザーの問いやセッションをリポジトリへ載せることになったら、データの区分を判じ直す。
  ただしそのときの論点はライセンスより先にプライバシーである
- 同梱する外部由来が二つ以上になったら、README の一節では追えなくなるので `THIRD-PARTY-NOTICES` の形へ移す
