# 0035. 「答えを与えない」を「一方向に閉じた材料を出さない」として検査可能にする

- **状態**: 採用
- **決定日**: 2026-07-19
- **関係する ADR**: なし

## 文脈

`docs/VISION.md` の最重要の設計制約は「AI は答えを与えない」である。
この制約をペルソナのシステムプロンプトへ書くとき、「知識を出さない」と読むか、別の読み方をするかを決める。

このレコードは #198（docs の md を「md の持ち場」で照合し、持ち場でない内容を移す）で `docs/ARCHITECTURE.md`「二体 AI のオーケストレーション」節から後から割ったもので、決定日は元の決定日である。

## 決定

制約の実体は「**一方向に閉じた材料を出さない**」とし、検査できる形で置く。

| 規律 | 検査 |
|---|---|
| 対立を必ず添える | 一方の見方だけの材料が無い |
| 出典を添える | 材料に出所がある |
| 一度に最大 3 件 | 件数 |
| 未検証なら明示する | 断定の形をしていない |

置き場はペルソナ両体（`web/src/personas/`）の「材料の供給規律」節で、節があることは `tests/personas.test.ts` が検証する。

## 理由

「知識を出さない」と読むと材料が枯れて発酵が止まる。
実地の観測では、外部知識を大量に供給しても問いは潰れなかった。
供給されたのが結論ではなく係争中の材料だったからである（矛盾する研究を矛盾したまま渡し、解消は人間がした）。

採らなかった案と、それを採らなかった条件。

- **知識を一切出さない** — 材料が無くても発酵が進むなら足りる。
  実地では材料が無いと議論が始まらなかった
- **モデルの判断に任せる** — 破られたことを検査できるなら足りる。
  否定形で書かなければ、破られたことを人間が観察できない

## 帰結

- ペルソナ両体の「材料の供給規律」節が上の 4 項を持つ
- `tests/personas.test.ts` が節の有無を見る（中身の遵守は L5 の官能）
- 培地（`extensions/fermentation-and-outlets.md`「D. 培地」）の外部材料も同じ形（件数上限・対立の同梱・出典必須）で設計する

## 覆る条件

- 3 件の上限か対立の同梱が、対話を止めていると常用で判定されたら
- 材料の供給を培地が担う形になったら。
  そのときペルソナ側の規律は、対話中の追加供給にだけ効く形へ縮む
