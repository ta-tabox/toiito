# 0024. `.env*` を Claude が触ってよい範囲を、読みと書きで別々に引く

- **状態**: 採用
- **決定日**: 2026-09-02
- **関係する ADR**: 0014

## 文脈

記述と実態が食い違っていた。
`CLAUDE.local.md`（追跡外）は「`.env*` は権限設定で Claude が触れない。自分で書かず人間へ渡す」と書いていたが、`.claude/settings.json` にもグローバル設定にもそれを裏付ける綴りは一つも無く、実際には Claude が普通に書き込めた。
発覚したのは PR #144（AI のスコープでモジュールを切り直す）で、env を `TOIITO_ANTHROPIC_*` へ改名したとき `web/.env.example` の旧名だけが残り、記述に従って人間へ回したのに Claude 自身が直せた。

この食い違いは片方向にしか倒れない。
「触れない」と信じて人間へ渡す限り実害は遅れで済むが、逆に「触れる」と判断した回に本当は触ってはいけないファイルだったら、秘密が公開リポジトリの差分へ載る。
だから記述を実態へ合わせるのでは足りず、どちらが望ましいかを先に決める必要があった（#151（ドットファイルを Claude が触ってよい範囲を決める））。

## 決定

押さえ方は `.claude/settings.json` の `deny` に置き、**読みと書きで別々の線を引く**。

- **読み**: 秘密を持つ綴りだけを塞ぐ。
  `Read(**/.env)` `Read(**/.env.local)` `Read(**/.env.*.local)` `Read(**/.env.development)` `Read(**/.env.production)` `Read(**/.env.test)`。
  `web/.env.example` は Claude が読める
- **書き**: `Edit(**/.env*)` の一律で、例外を置かない。
  `web/.env.example` も Claude は書けない

規約の文は `CLAUDE.md`「環境変数（`.env*`）」が持つ。
コマンド全文を見るフックは足さない。

## 理由

線を分けたのは、読みと書きで危険の向きが逆だからである。
読んで漏れるのは秘密を持つ側だけで、`web/.env.example` は追跡対象で秘密を含まないので読んでも漏れない。
逆に書いて漏れうるのは追跡対象の `web/.env.example` だけで（`.env.local` は `web/.gitignore` の `.env*` が差分から外す）、実キーが公開リポジトリへ出る経路はそこにしかない。
同じ線を読みと書きへ引くと、どちらかが必ず的を外す。

`web/.env.example` を読める側へ置いたのは、`web/README.md` の env 表との突き合わせに要るためでもある。

`deny` に例外は書けない——評価順が deny → ask → allow で、より狭い allow は deny を覆さない——ので、線は綴りそのもので引くしかない。
その帰結として読み側は列挙になり、将来ここに無い綴りを使い始めれば穴が開く。
書き側を一律にしてあるのは、穴が開いても**書かれる事故だけは起きない**ようにするためである。

権限層が届く範囲も測った（`code.claude.com/docs/en/permissions`）。
`Read` の deny は Read だけでなく Edit と Write を同じパスで塞ぎ、Bash の `cat` / `head` / `tail` / `sed`、`>` `>>` のリダイレクト先、シンボリックリンクの実体にも及ぶ。
届かないのは `python` や `node` のスクリプトが自分でファイルを開く経路で、そこを塞ぐ手段は sandbox（OS レベル）しか無い。
なお `Write(パス)` と書いた規則は受理されるが参照されないので、パス規則は `Read` と `Edit` の二つで書く。

採らなかった案と、それを採らなかった条件。

- **読みも書きも `.env*` で一律**。
  穴は開かないが `web/.env.example` を読めなくなり、`web/README.md` の env 表との突き合わせが機械の手から離れる。
  読める側に置いても漏れないと分かっている以上、代償の方が大きい。
  読み側の列挙が実際に破れて事故が起きたら、こちらへ倒す
- **読みも書きも綴りを列挙し、`web/.env.example` を書ける側へ置く**。
  PR #144 の摩擦は消えるが、実キーが公開リポジトリの差分へ載る唯一の経路を開けたままにする。
  摩擦は遅れで済み、漏洩は済まない
- **規約の文だけで持ち、機械では止めない**。
  #152（`main` の ruleset が enforcement: disabled で、誰にも効いていない）が同じ軸——機械で止めるか規律だけで持つか——で決着し、`enforcement: active` の側が選ばれている。
  ここで文だけへ戻す理由が無い。
  機械層が届く範囲は狭いが、狭いのは「素直に触りに行く経路」の外側だけで、この issue が問題にしている危険は素直な誤りの側にある
- **コマンド全文を見るフックを足す**（`guard-force-push.sh` / `guard-gh-api.sh` と同じ型）。
  `gh api` でフックが要ったのは、綴りが一つしか無く `allow` か `ask` の二択になり、素通しすべきコメント投稿まで潰れたからで、**フックが無いと層を分けられなかった**。
  `.env*` は `Read` と `Edit` で層が分かれるので、フックは取りこぼしの上乗せにしかならない。
  しかも上乗せできるのはコマンド行に綴りが現れる場合だけで、変数やスクリプトファイルへ畳まれた綴りは同じ手では拾えない。
  維持するフックが一本増える代償に見合わない
- **sandbox を有効にする**。
  唯一サブプロセス経路まで届くが、Bash の走り方が全部変わり、`pnpm` / `docker compose` / `prisma` の挙動を確かめ直すことになる。
  #151 の範囲を大きく超える

## 帰結

- **`web/.env.example` の更新は人間の手に入る**。
  PR #144 で起きた「旧名だけ残る」形は、事故でなく決定の帰結として残る。
  変数の一覧と意味は `web/README.md`
- **worktree に `.env.local` を作れなくなる**。
  これは新しい制約ではない。
  `.worktreeinclude` が「本体と同じ `DATABASE_URL` を持つコピーは、worktree の migration を本体の開発用 DB へ積む」としてこのファイルを対象から外しており、文だけで持っていたその決定を機械が裏書きした形になる。
  値が要るだけの場面（`prisma generate` の `DIRECT_URL`）はコマンドの前置きで渡せるので、deny は邪魔しない
- **リモートは変わらない**。
  `.env.local` を書くのは `.claude/hooks/session-start.sh` で、フックはハーネスが直接叩くのでツールの権限規則を通らない
- **届かない経路は残る**。
  `python` / `node` のスクリプト越しの書き込みと、`git add -f` による追跡は権限層の外にある。
  そこは `CLAUDE.md`「環境変数（`.env*`）」の規約が持つ
- **`CLAUDE.local.md` の記述がようやく実態と合う**。
  追跡外のファイルなので、文面の更新は人間の手で行う

## 覆る条件

- **`web/.env.example` を人間の手に置く摩擦が実際に重くなったとき**（旧名が残る事故が繰り返される、env の増減が頻繁になる）。
  書き側の一律をやめ、`web/.env.example` を書ける側へ移す
- **読み側の列挙に無い綴りを使い始めたとき**（`.env.staging` など）。
  列挙を足すか、読みも `.env*` の一律へ倒す
- **sandbox を有効にしたとき**。
  OS レベルで塞がるので、この deny は下限としてしか要らなくなる
