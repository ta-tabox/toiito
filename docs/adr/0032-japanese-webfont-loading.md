# 0032. 和文の Web フォントは preload を切り、ウェイトを画面に出る分だけ宣言する

- **状態**: 採用
- **決定日**: 2026-09-08
- **関係する ADR**: なし

## 文脈

`web/src/app/layout.tsx` は `next/font/google` で二書体を読み込む。
見出しの明朝が Shippori Mincho、本文と UI のゴシックが Zen Kaku Gothic New で、どちらを何に当てるかは `.claude/rules/design.md`「書体と字組み」が決めている。

決まっていないのは読み込み方である。
和文の Google Fonts は欧文と条件が違う。
1 ウェイトが `unicode-range` で百本を超えるサブセットに分かれ、そのうちどれが要るかは実際に描く文字を見るまで決まらない。
欧文の書体を読むときの既定（`preload: true`・`subsets` を明示）をそのまま当てると、要るかどうか分からないサブセットを大量に先読みすることになる。

読み込み方の理由は `layout.tsx` の JSDoc に 14 行で書かれていたが、これは 1 関数 2 文までという `.claude/rules/coding.md`「コメント」節の上限を大きく超える。
上限を超える理由は ADR へ移すと規約が決めているので、ここへ置く。

## 決定

`next/font/google` の呼び出しを次の形に固定する。

- **`preload: false`** を両書体に付ける
- **`weight` は実際に画面へ出るものだけ**を挙げる（明朝は `["400"]`、ゴシックは `["400", "700"]`）
- **`subsets` は書かない**
- **欧文専用の書体を足さない**。
  日付と数字は和文書体の従属欧文へ預ける

## 理由

**`preload: true`（next/font の既定）を採らなかった条件**: 和文は数十本以上のサブセットに割れており、どれが要るかは本文の文字を見るまで決まらない。
先読みできる根拠が無いものを先読みすると、使わないサブセットの取得が初期表示と競合する。
覆るのは、初期表示の遅さが実測で問題になり、かつ先読みすべきサブセットが特定できるようになったときである。

**全ウェイトを挙げなかった条件**: 使わない一段を足すと、そのウェイトのサブセット百本余りが初回のビルドと `pnpm dev` の起動に乗る。
画面へ出ないものの取得を待つ理由が無い。
太字を画面へ足すときは、そのときウェイトを一段足す。

**`subsets` を書かなかった条件**: `subsets` が決めるのは preload の対象だけで、生成される `@font-face` は Google が返す `unicode-range` の全量になる。
`preload: false` と併記しても生成物が変わらないので、書いても振る舞いが変わらない。
そのうえ `["latin"]` と書くと、和文が別サブセットとして漏れるように読める。
振る舞いを変えず誤読だけを生むので書かない。

**欧文専用の書体を足さなかった条件**: 和文と欧文で字面の大きさとベースラインが揃わない（`.claude/rules/design.md`「書体と字組み」）。
数字が縦に並ぶ箇所は `font-variant-numeric: tabular-nums` で揃えるので、書体を分けなくても桁は揃う。

## 帰結

- `layout.tsx` の JSDoc は、`preload: false` と `subsets` を書かないことの二点だけを残し、理由はこの ADR を指す一行に畳む
- ウェイトを増やす変更は、画面に出る場所とセットでしか入らない
- 初期表示の体感は `docs/DESIGN.md`「残す摩擦」の判断対象で、計測は入っていない

## 覆る条件

- 初期表示の遅さが実測で問題になり、先読みすべきサブセットが特定できるようになったら。
  そのとき `preload` を戻す
- `next/font` が和文サブセットの扱いを変え、`subsets` が生成物に効くようになったら
- 欧文専用の書体を当てる判断が `.claude/rules/design.md`「書体と字組み」の側で覆ったら
