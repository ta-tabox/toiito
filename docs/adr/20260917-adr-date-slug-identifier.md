# ADR の識別子を、連番から決定日と slug の組にする

- **状態**: 採用
- **決定日**: 2026-09-17
- **関係する ADR**: なし

## 文脈

ADR の識別子は 4 桁の連番で、欠番を作らない規約だった。
次の番号は `docs/adr/README.md` の一覧を見て決めるが、一覧は未マージのブランチの ADR を知らないので、並行するセッションが同じ番号を取っても PR を出すまで気付けない。

| 日付 | 起きたこと | 後始末 |
|---|---|---|
| 2026-09-09 | #68（ログイン）と #64（ペルソナ）のセッションが同じ番号を取った | 後から PR を出した側が改番した |
| 2026-09-15 | 取り下げた ADR の番号が欠番になった | PR #286（ADR の繰り下げ）が後ろの 10 本を一つずつ繰り下げた |

改番は `docs/adr/` の中の相互参照だけでなく、コードのコメント・現況の文書・open な issue と PR の本文にある参照まで動かす。
worktree を並行させる運用は続くので、番号の取り合いは今後も起きる。

## 決定

1. ADR の識別子を、決定日（`YYYYMMDD`）と決定を表す slug をハイフンでつないだ文字列にし、ファイル名はその識別子に `.md` を付けたものにする
2. 同じ日の ADR は slug で区別し、同じ日の中の順序は持たない
   識別子が既存のものと完全に一致したら、後から書く側が slug を変える
3. 連番で書いた既存の ADR も同じ形へ改名し、本文とヘッダ、ADR の外の文書とコメントにある参照を新しい識別子へ置き換える
   旧番号は一覧の列に残し、旧番号で書かれた参照から ADR を探せるようにする
4. ADR の外から指すときは `ADR-<識別子>（決定の名前）` と書き、ADR の本文とヘッダでは識別子だけを書く
5. 見出しは決定の一行だけにし、識別子を重ねて書かない

決定時点の規約の文面と一覧の書式の現況は `docs/adr/README.md` が持つ。

## 理由

- 識別子を決定日と決定の内容だけから導けば、他のブランチの状態を知らなくても衝突しない名前が決まる
- 連番でないので、取り下げても欠番にならず、改番が要らない
- 識別子が完全に一致する場合は git が同じパスの追加として衝突させるので、重複が黙って入らない
- 同じ日の中の順序を持つと、日の中で番号の取り合いが再び起きる
- 識別子を stem と一致させれば、本文の参照を grep するだけでファイルに当たる
- `.claude/rules/writing.md` は番号や記号で事物を指すときに人間が分かる名前を添えるよう求めており、ADR の外で括弧に決定の名前を添える形はその規則をそのまま満たす
- 改名しない場合、旧番号の ADR と新しい識別子の ADR が一覧とディレクトリで二つの形に割れ、参照の書き方も二通り残る
- 旧番号は open な issue・PR の本文と適用済みの migration のコメントに残り、そこは書き換えられないので、一覧に列として残す

採らなかった案と、それを採らなかった条件。

- **連番を続け、番号を issue で予約する**。
  既存の形が変わらない。
  予約の手順を並行する全セッションが守る前提になり、取り下げたときの欠番も残るので採らなかった
- **既存の ADR を改名しない**。
  参照が一つも動かない。
  識別子の形が二通り残り、書き手が ADR ごとにどちらの形かを判じることになるので採らなかった
- **日付の後に日内の連番を付ける**（例: `20260917-01-…`）。
  同じ日の中の順序が残る。
  日の中で番号の取り合いが再び起きるので採らなかった
- **UUID や ULID を識別子にする**。
  衝突がほぼ起きない。
  識別子から中身も時期も読めず、参照の横に置く名前がすべての意味を持つことになるので採らなかった
- **本文の参照を旧番号のまま残し、対応表から探させる**。
  ADR の本文へ手を入れずに済む。
  本文を読むたびに対応表で旧番号を探すことになるので採らなかった

## 帰結

- 次の ADR からは一覧を見て番号を決める手順が無くなり、決定日と slug だけで名前が決まる
- 既存の ADR の本文とヘッダの参照が新しい識別子へ置き換わる。
  識別子だけを置き換え、決定・理由・帰結・覆る条件の意味は動かさないので、規約 4 の例外（意味を変えない語彙の置き換え）に当たる
- ADR を指すコードのコメントと現況の文書のパスが変わる
- 適用済みの migration のコメントは旧番号のパスのまま残る。
  Prisma が適用済みの migration のチェックサムを照合するので書き換えず、一覧の旧番号の列から探す
- open な issue と PR の本文の旧番号も書き換えず、一覧の旧番号の列から探す
- 一覧の並びは識別子の辞書順になり、ディレクトリの並びと一致する

## 覆る条件

- 並行して ADR を書く運用がなくなり、番号の取り合いが起きなくなったとき
- 同じ日に同じ slug を取り合う衝突が繰り返し起きたとき
- ADR をリポジトリの外のツール（番号を前提にする ADR 管理ツールなど）で扱うことになったとき
