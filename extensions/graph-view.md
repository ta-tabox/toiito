# 拡張構想: グラフビュー（発酵の地層を眺めるモード）

記録日: 2026-07-07。
状態: **アイディア（未着手）**。
本体 MVP（ARCHITECTURE.md / NEXT.md）とは分離した拡張枠。
MVP の完了条件には含めない。
着手判断は MVP 常用後（メモが実データとして溜まってから）。

## なぜ（VISION との接続）

対話は堆積して振り返れるもの、が VISION の前提。
現状の振り返り口は「時系列（チャットログ）」と「メモ一覧からの逆引き」の二つだが、どちらも線的。
問い・キーワード・会話の**つながり**は線では見えない。
Obsidian のグラフビューのイメージで、堆積した地層を俯瞰する第三の口を作る。

グラフは答えを出す装置ではなく**再訪の入口**。
「このキーワード、あの問いでも出てたな」という偶発的な再会を誘発する。
スローダウンの道具という設計原理と整合。

## 二つの視点

1. **時系列ビュー** — 会話の流れを時間軸で。発話の順序・密度が見える
2. **グラフビュー** — 問い・メモ（キーワード）・メッセージをノードに、参照関係を辺に。
   時間を捨てて関係だけを見る

同じデータの二つの射影。切替はモードスイッチ（同一ページ内）。

## スコープの段階

### Phase 1: セッション内グラフ（最初のターゲット）

一つの問いセッション内で閉じる。

- ノード: 問い（中心）/ メッセージ（human・ai_a・ai_b で色分け）/ メモ
- 辺:
  - message → message（発話の連鎖 = 時系列の背骨）
  - memo → message（アンカー。`memos.message_id` で既にある）
  - question → session 先頭
- 時系列ビューは同じノード集合を時間軸レイアウトで並べ直すだけ（レイアウト関数の差し替えであってデータの差し替えではない）

### Phase 2: memo_links の実装

グラフが「見るだけ」から「編む」に変わる転回点。
`memo_links` テーブルは ARCHITECTURE.md で予約済み（id, from_memo_id, to_memo_id, kind）。
メモ間リンクを張る UI（グラフ上でノード二つ選択 → リンク）を足すと、人間が張った辺が構造ノイズ（機械的な連鎖辺）と区別されて浮かぶ。

### Phase 3: メタグラフ（アプリ全域の走査）

問い・セッション・メモを横断する俯瞰。
ここでの鍵は**キーワードの正規化**: 同一キーワードのメモを一つのキーワードノードに束ねることで、初めて問い同士が間接的に接続される（キーワードがハブになる）。

- ノード: questions / keywords（束ね） / sessions（折りたたみ可）
- 正規化は完全一致から始める。
  表記ゆれ吸収（embedding 類似など）は発酵後の課題として開けておく
- 逆引きページ（MVP）はこのメタグラフのリスト射影とみなせる。
  つまり Phase 3 は逆引きの上位互換であって別機能ではない

## 実装方針（HARNESS の作法に従う）

「lib 関数 + テスト → UI 配線」の順。

1. **lib 層**: `web/src/lib/graph.ts`
   - `buildSessionGraph(sessionId) → { nodes, edges }`（Phase 1）
   - `buildMetaGraph() → { nodes, edges }`（Phase 3）
   - どちらも db.ts の repo 関数の join 一本で組める（SQLite/Postgres 両立の契約を崩さない）。
     純関数部分（rows → graph 構造）を切り出してテスト
2. **UI 層**: `web/src/app/q/[id]` にビュー切替、メタグラフは `/graph` を新設
3. **描画**: 初期は d3-force + SVG の自前描画で十分（個人用・ノード数百程度。
   Cytoscape.js / Sigma.js は数千ノード超えたら再検討）。
   時系列レイアウトは force を使わず x=時間 の決定的配置
4. **テスト**: グラフ構築の純関数は Vitest でノード数・辺の整合性を検証。
   描画は Playwright E2E（P1 のシード基盤と同時期なら相乗り）

## 前提（依存関係）

- **メモ機能の完成が先**（MVP 残り半分）。
  メモが無いグラフはただの一本鎖チャットログで、時系列ビューとの差分がない
- 逆引きページの実装が Phase 3 のデータ経路の先行検証を兼ねる

## 開いている問い

- メッセージをノードにすると長文でノードが意味を失う。
  要約ラベル？それともメモだけをノードにしてメッセージは辺の文脈に潜らせる？
- 「グラフを眺める」体験がスローダウンに寄与するかは実測するしかない。
  俯瞰は往々にして「わかった気」を生む——安易な答えへの逃避を防ぐ仕掛け ── の対極になり得る点は自覚しておく
